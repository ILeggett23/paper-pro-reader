# Paper Pro Reader backend

This directory contains the small authenticated backend used by Phase 4. The
Paper Pro sends a provider-neutral reading request to this service; only the
service calls the configured AI provider. An OpenAI API key is never sent to or
stored on the reader.

## Requirements

- Node.js 20 or newer.
- A revocable device access token generated by the operator.
- An OpenAI API key for real provider calls.
- HTTPS at the public production endpoint.

The server uses Node's built-in HTTP and `fetch` implementations and has no
runtime package dependencies.

## Configuration

Copy `.env.example` to a local `.env` only if that suits the development
environment. `.env` files are ignored by Git and are not loaded automatically;
export the values through the shell, process manager, container platform, or
secret manager before starting the server.

Required:

- `DEVICE_ACCESS_TOKEN`: revocable application-level bearer token configured
  on the reader. It is not an OpenAI credential.
- `OPENAI_API_KEY`: server-side provider key.

Optional:

- `PORT`: local listen port, default `8787`.
- `HOST`: listen address, default `127.0.0.1`; container platforms may require
  `0.0.0.0` behind their authenticated HTTPS ingress.
- `OPENAI_MODEL`: replaceable provider model, default `gpt-5.4-mini` for the
  Phase 4 development configuration.
- `PROVIDER_TIMEOUT_MS`: upstream provider timeout, default `30000`.
- `IDEMPOTENCY_DB_PATH`: restart-safe completed-response file, default
  `./data/idempotency.json`.
- `IDEMPOTENCY_TTL_SECONDS`: completed request retention, default `86400`.

Never commit `.env`, a device token, or a provider key. Avoid putting secrets
directly in reusable shell history. Production deployments should use their
host's encrypted secret facility.

## Run locally

From `backend/`:

```sh
set -a
. ./.env
set +a
npm start
```

The process binds to `127.0.0.1` by default. Local development may configure
the reader with `http://127.0.0.1:8787`. Remote device access must terminate
HTTPS at a reverse proxy, load balancer, tunnel, or platform ingress and
forward to the local process. Do not disable certificate verification.

Endpoints:

- `GET /health`: public liveness response with no secrets.
- `GET /v1/config`: authenticated protocol diagnostic.
- `POST /v1/reading/answer`: authenticated, versioned answer endpoint.

## Authentication

The reader sends `Authorization: Bearer <DEVICE_ACCESS_TOKEN>`. The backend
uses a constant-time comparison and returns a stable `authentication` error
category on failure. Use a long random value, scope network access where
possible, rotate the token if the device is lost, and restart the service after
rotation. This token can create reading-assistant requests but cannot be used
as an OpenAI API key.

## OpenAI provider

`src/providers/openai.mjs` implements the provider interface with the OpenAI
Responses API at `POST /v1/responses`. The configured model must support image
and text input for handwritten questions. The adapter sends `store: false`, a
reading-companion instruction, the user's typed question or bounded
handwriting image, and a separately labeled JSON block of untrusted quoted
book context. It does not enable tools,
function-calling, web search, streaming, or provider-side conversation history.

The model is selected exclusively with `OPENAI_MODEL`; the device protocol and
saved response format are provider-neutral.

## Validation and privacy

The backend rejects bodies over 400,000 bytes, questions over 1,024 UTF-8 bytes,
selected passages over 8,192 bytes, surrounding fields over their documented
limits, total source text over 16,384 bytes, unsupported schemas, and unsupported
question types. Device-local file identities and navigation anchors are
rejected if transmitted.

Handwriting accepts only canonical base64 `image/png` data, up to 262,144
decoded bytes, 1,200 x 512, and 600,000 pixels. PNG signature, IHDR, dimensions,
and actual/declared byte count are checked. Images are processed in memory,
never fetched from client URLs, never written to server disk, and never logged.
The one-pass response includes qualitative clear/uncertain/unreadable
recognition, optional recognized question text, clarification state, and the
answer.

Ordinary logs contain request ID, status, duration, and stable error category.
They do not contain full questions, book excerpts, answers, bearer tokens, or
provider keys. Provider output is treated only as text and is never executed.

The production entrypoint deduplicates completed request IDs across restart for
24 hours, up to 1,000 entries, using an atomic mode-0600 JSON file in a
mode-0700 directory. It stores request ID, completed response, creation time,
and expiry only; no image, prompt, book context, or credential is retained.
Multi-instance deployments still require a shared durable adapter behind the
same `run(requestId, task)` contract.

## Tests

```sh
npm test
```

Tests use mocked providers and do not require an OpenAI API key. They cover
health, authentication, validation and size limits, prompt separation,
provider success and failures, restart-safe idempotency, privacy-safe logging, and the
OpenAI Responses adapter. A live provider smoke test is intentionally opt-in
and must never print or persist its key.

## Deployment

The backend is host-neutral. Run it behind any production HTTPS ingress that
supports Node.js processes. Configure secrets in the host, set request and
concurrency limits appropriate for the deployment, retain TLS verification,
and use one shared idempotency store if the service has multiple instances.
No account, note sync, book sync, or public AI relay is included in Phase 4.
